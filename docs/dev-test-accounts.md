## 2026-09-16 — 명시적으로 요청한 성인 인증 테스트 예외

사용자가 성인 인증 DB 강제 갱신과 제한 없는 친구 테스트를 요청했다. 위 기존 두 계정의 `profiles.age_verified_at`만 갱신했고, 원래 값(null)과 적용 시각을 **운영자만 변경 가능한** Auth `app_metadata.dev_social_test`에 기록했다. `source=manual_test_not_pass`이며 실제 PASS 결과나 실명 검증을 뜻하지 않는다. 원격 두 계정의 `my_privacy_status.age_verification_complete=true`, 양쪽 `list_chat_threads`에 상대가 표시되는 것을 인증된 요청으로 확인했다. 테스트용 확인 세션은 메모리에서만 사용하고 해당 세션만 종료했다. 실제 메시지를 보내거나 이용자의 기존 세션을 로그아웃시키지 않았다.

재실행·복구는 서버 전용 운영 스크립트로 한다. 지정된 dev URL과 두 계정 ID/이메일이 모두 일치해야 실행된다. 다른 계정이나 프로젝트에는 적용하지 않는다.

```bash
node scripts/dev-social-test.mjs status
node scripts/dev-social-test.mjs enable   # 두 계정의 테스트 인증 상태 활성화
node scripts/dev-social-test.mjs connect  # 교차 횟수·요청 한도·쿨다운 없이 두 계정 연결
node scripts/dev-social-test.mjs restore  # 테스트 인증 원복, 다른 시각의 실제 인증은 덮어쓰지 않음
```

`restore`는 친구를 삭제하지 않는다. 실제 운영 전 테스트 인증을 반드시 원복해야 한다. 자동 만료는 설정하지 않았다. 차단·제재·동의·로그 공개·원본 GPS 권한은 완화하지 않았다. 원격 익명 요청의 `profiles`, `location_points` 조회는 각각 42501인 것을 재확인했다.

### 앱의 개발용 친구 연결 버튼

- 마이그레이션 `036` 및 `DevFriendsPanel`을 추가했다. 개발 빌드의 발견 화면에서 서버가 허용한 테스트 계정끼리 바로 친구 추가를 할 수 있다. 일반 계정에는 표시되지 않고 서버도 호출을 거절한다.
- 표시·접속 판정은 `private.dev_test_pair_allowed`로 통합했다. 양쪽 모두 운영자 지정 테스트 표시가 있어야 하며 차단·제재·필수 동의·삭제 신청 제한은 유지한다. 사용자 편집 가능 `user_metadata`로는 활성화할 수 없다. 실제 수락 요청이나 교차 GPS 기록은 생성하지 않는다.
- 타입 검사 및 로컬 DB 전체 329개, 운영 도구 보호 검사 3개 통과.
- **2026-09-16 원격 배포 완료:** CLI 권한 부족 403 이후 사용자 승인으로 로그인된 SQL Editor에서 정원 `033`~`035`와 테스트 친구 `036`을 단일 트랜잭션 적용하고 이력을 기록했다. 두 계정 모두 `get_garden` 정상 응답(참여 전 null), `list_dev_test_runners` enabled=true/상대 1명, 대화 목록 상대 1명을 확인했다. 기존 인증/친구 데이터 및 정원 공개 설정은 이번 배포에서 변경하지 않았다. 실제 러닝 지급/편집/방문 종단 검증은 별도다.
