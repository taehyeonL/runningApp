## 실제 정원 연결 — 우선순위 1~5

- 정책 v1은 서버 `private.garden_policy()`와 `private.garden_catalog`가 원본이다. 500m당 꽃 25%, 나무 20%, 돌 10%, 달빛 버섯 3%, 별빛 분수 2%, 미획득 40%. 앱은 서버 카탈로그로 확률을 표시한다. 기존 TS 순수 함수는 시뮬레이션/격자 테스트용이며 지급 권한이 없다.
- 초기 16칸, 누적 42km마다 4칸씩 추가한다. 큰 정원은 32칸씩 페이지로 탐색한다. 시작 선물은 꽃·나무·돌 각 1개이며 재진입으로 다시 받지 않는다.
- 홈에서 선택 참여를 확인한 뒤 실제 정원을 만든다. 참여 이후 **시작된** 러닝만 적립한다. 과거 기록·참여 전 워치 기록의 늦은 업로드는 소급 지급하지 않는다. 수집 중단/재개는 가능하며 기존 아이템과 무료 기록 기능은 유지한다.
- 서버 완료 트리거는 `server_validated`와 서버의 `rejection_reasons`를 검사한다. 매칭 전용 `distance_below_3km`는 제외하되 다른 품질 탈락 사유는 허용하지 않는다. 500m 미만 거리는 누적하고 추첨·확장은 한 트랜잭션에서 처리한다.
- 소유자 행 잠금 및 계정/세션·계정/원본 기기 기록 키 유일성으로 재시도·동시 완료·삭제 후 동일 기기 기록 재전송의 중복 보상을 차단한다. 지급 결과·기회 수·정책 버전만 보존하며 GPS는 저장하지 않는다. 기록 삭제 후 이미 받은 보상과 누적 거리는 유지되고 계정 파기 시 전체 정원 원장이 연쇄 삭제된다.
- 보관함은 종류별 소유 수량으로 표시한다. 배치·교체·회수는 자동 저장하고, 서버가 수량·셀 경계·중복 칸을 검사한다. 다른 화면과 충돌하면 저장을 거절하고 새로고침을 안내한다. 클라이언트의 임의 메타데이터는 저장하지 않는다.

## 사용자 확정 규칙

- 일반 러닝에서도 500m마다 무작위 아이템 획득 기회가 생긴다. 일반 아이템뿐 아니라 희귀 아이템도 반드시 양의 확률로 드롭된다.
- 매일 달리기에 적합하다고 검토된 구역 중 무작위 구역을 지정한다. 그 구역을 유효하게 지나 러닝을 완료하면 희귀 아이템을 지급한다.
- 수집한 아이템으로 개인 정원을 꾸민다. 여러 러닝의 누적 거리 42km마다 정원 공간이 확장된다.
- 주인이 허용한 범위에서 매칭 카드 또는 친구 목록으로 정원을 방문한다. 방문으로 요청·채팅 자격이 추가되지는 않는다.

## 일반 드롭

구현: `src/features/garden/garden-rules.ts`의 `rollGardenDrop`, `gardenProgress`.

1. 서버가 검증한 누적 유효 거리의 500m 단위마다 추첨 기회를 산출한다. 남은 거리는 다음 러닝으로 이월한다. 250m + 250m는 1번, 5km는 10번의 기회다.
2. 아이템별 가중치와 미획득 가중치를 설정한다. 한 기회에 아이템 하나 또는 미획득이다. 개별 확률은 해당 가중치 / 전체 가중치 합이다.
3. 일반·희귀 아이템이 각각 하나 이상 있어야 하며 각 아이템 가중치는 양수다. 희귀 확률 0, 중복 ID, 잘못된 가중치를 거부한다.
4. 구역 보상은 같은 목록의 희귀 아이템만으로 추첨하여 하나를 확정 지급한다. 구역 전용 희귀 아이템은 만들지 않는다. 보통 루트에서도 같은 아이템을 얻을 수 있다.
5. 구역을 방문한 러닝도 일반 거리 보상을 동일하게 얻는다. 구역 보상은 추가 보상이며 계정·한국 날짜 기준 하루 1회 지급하는 초기안이다.

3km 조건은 매칭 조건이다. 정원 보상을 위해 짧은 러닝을 배제하지 않으며, 거리·GPS 검증과 소셜 자격을 구분한다. 앱에서 임의 거리를 넣어 보상을 확정할 수 없도록 실제 지급은 서버에서만 한다.

## 일일 구역: 안전 후보 필터 → 무작위 선정 → 당일 고정

구현: 같은 파일의 `isGardenZoneEligible`, `selectDailyGardenZone`.

지도상의 무작위 좌표나 공원 이름만으로 안전하다고 간주하지 않는다. 운영 검토와 최신 통제 정보를 가진 구역 목록이 입력이다. 넓은 활동 지역별로 다음 조건을 모두 통과해야 추첨한다.

- 등록 유형: 공원, 러닝 트랙 또는 검토된 보행 전용 산책로.
- 활성 구역이며 공개 접근이 가능하고 차량 동선과 분리된 것으로 검토됨.
- 안전 검토가 승인됐고, 승인 유효 기간이 보상 운영 시간 전체를 포함함.
- 개방 시간과 낮 시간 등 검토된 이용 가능 시간이 보상 운영 시간 전체를 포함함.
- 공사·폐쇄·침수·기상 등 위험 정보가 `clear`이며 그 정보의 유효 범위가 운영 시간 전체를 포함함. 미확인·유효 기간 만료는 제외함.
- 요청한 넓은 활동 지역과 일치함. 사용자의 집·직장·반복 출발점을 선정 기준으로 사용하지 않음.

통과한 구역 중 균등 추첨한다. 같은 날짜에도 지역별로 구역을 마련해 한 장소로 이용자가 몰리지 않게 한다. 날짜/지역/운영 시간별 선정 결과는 서버에 한 번 저장하여 앱 새로고침으로 바뀌지 않게 한다. 한국 서비스의 날짜 경계는 Asia/Seoul이다.

후보가 없으면 `null`을 반환하고 그날 구역 보상을 제공하지 않는다. 위험 구역이나 미검토 구역으로 대체하지 않는다. 일반 드롭과 개인 정원은 계속 이용 가능하다.

선정 이후에도 노출·방문 판정 때 같은 안전 함수를 다시 호출한다. 새 통제 정보가 들어오면 선정된 구역도 중단하고, 이미 방문했지만 늦게 동기화한 기록은 방문 당시의 유효 일정·통제 이력으로 검증한다. 현재 함수는 입력된 안전 정보를 검사할 뿐, 위험 데이터 수집이나 현장 안전 보증을 수행하지 않는다. 실제 구역으로 향하는 접근 경로의 안전까지 보장하지 않는다.

## 전국 격자 배분과 실제 보상 구간

격자는 장소 배분 단위다. `GARDEN_ALLOCATION_GRID`의 한 변 2,500m는 초기 조정 가능한 가설이며, 정원 확장 단위나 GPS 비식별화 격자와는 관계없다. 실제 전국 구역 데이터는 아직 없다.

- 공공 장소의 대표 지점을 데이터 적재 시 EPSG:5179 미터 좌표로 변환한다. `gardenGridCell`은 그 좌표를 고정 격자에 배정한다. 위도·경도를 그대로 전달하지 않는다. 이 함수는 좌표 변환을 수행하지 않으며 입력 좌표계 검증은 적재 계층의 책임이다.
- 공원·트랙별 고정 `placeId`와 대표 지점을 두어 여러 격자에 걸친 장소도 한 지역·한 격자에만 배정한다. 같은 장소가 서로 다른 격자/지역에 등록되면 입력을 거부한다.
- 실제 보상은 `segment.path`에 등록된 검토된 공공 러닝 구간에 붙는다. 격자 중심점, 임의 좌표 또는 사용자 경로를 보상 위치로 만들지 않는다.
- `selectDailyGardenGrid`는 각 격자에서 같은 안전 판정을 거친 후보 구간 중 최대 하나를 뽑는다. 구간이 점 하나이거나 최소 유효 통과 거리보다 짧으면 제외한다. 안전 후보가 한 곳이면 다시 뽑힐 수 있고, 없으면 빈 선정 결과를 남긴다. 등록조차 없는 격자는 생성하지 않는다.
- `neighbouringGardenCells`는 현재 조회 격자와 이웃 8개 격자를 포함한다. 앱의 지도 탐색에서 인접 보상을 확인할 때 쓰며 사용자 위치 공개 또는 이동 경로 유추에 쓰지 않는다.
- 날짜·지역·격자·운영 시간별 선정은 서버에서 한 번 저장한다. 현재 순수 함수는 저장하지 않으므로 앱에서 매번 실행하는 방식으로 연결하지 않는다. 선택 이후 재검토·통제 취소도 별도로 연결해야 한다.
- 지도 UI는 검토된 보상 구간과 아이템만 보여주는 후속 구현이다. 현재 체험 화면에는 실재하는 보상 장소를 표시하지 않는다. 전국 자동 안전 구역 생성이나 GPS 구간 매칭을 구현한 것으로 간주하지 않는다.

## 정원 꾸미기 체험

로그인 화면의 `러닝 정원 꾸미기 체험` 또는 홈의 `나의 러닝 정원`에서 진입한다. 예시 아이템으로 4×4 정원에 배치·이동·교체·회수할 수 있고, 방문자 화면 미리보기에서는 편집을 막는다. 아이템 인스턴스가 중복 배치되거나 잠긴 공간 밖으로 배치되지 않도록 `placeGardenDecoration`을 사용한다. 교체한 아이템은 보관함에 남는다.

체험임을 항상 표시한다. 예시 아이템을 실제 소유권·러닝 보상으로 처리하지 않으며 배치는 화면을 나가면 초기화된다. 익명 체험에는 실제 계정·친구·후보 데이터를 사용하지 않는다. ‘방문자 화면’은 내 예시 정원의 읽기 전용 렌더링이며 실제 친구 정원 방문 기능이 아니다.

## 지급·개인정보 경계: 서버 연결 시 필수

- 새로운 위치 기반 보상 목적을 설명하고 선택 참여 동의를 받는다. 러닝 외 상시 위치 추적은 하지 않는다.
- 구역 통과는 서버에서 품질 검증된 GPS로 판정한다. 품질 미달 단일 포인트나 포인트 사이의 직선 연결만으로 통과를 인정하지 않는다. 실제 경계·유효 구간 기준은 지형 데이터와 함께 후속 구현한다.
- 확률 추첨에는 서버 난수를 사용하고 정책 버전과 결과를 보존한다. 계정/누적 500m 순번 및 계정/일일 보상에 유일성 제약을 두어 동시 요청·재전송·앱 재실행으로 재추첨하거나 중복 지급하지 않는다.
- 42km 확장도 서버의 검증된 누적 거리로 계산한다. 원본 GPS를 보상 때문에 30일 이상 보관하지 않는다.
- 기록 삭제·공개 범위 변경은 계속 무료이며 제한하지 않는다. 보상 원장은 GPS 없이 최소 정보만 두고, 기록 삭제로 지급 순번이 재사용되지 않게 한다. 계정 삭제 시 정원·보관함·보상 원장도 파기한다.
- 타인에게는 정원 배치와 공개 허용된 아이템 외 획득 장소·시각·날짜·세션·획득 방식·방문 이력을 보내지 않는다. 희귀 아이템은 여러 구역과 일반 드롭에서 공통으로 얻는다.
- 방문 조회는 기존 서버 관계 판정과 정원 공개 동의를 함께 적용한다. 차단·제재·성인 인증·관계 해제·삭제 신청에 따른 회수는 목록, 정원 상세, 이미지 등 모든 표면에 동일하게 적용한다.
