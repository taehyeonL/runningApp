상세 순서와 출시 차단 항목은 [launch-readiness.md](launch-readiness.md)를 따른다. 원격 DB에는 누락 037, 202609240001 다음으로 `202609240002_launch_social_experience.sql`, `202609240003_private_discovery_and_plan_week.sql`을 순서대로 적용해야 한다. 이번에는 로컬만 적용했다. 소개 상세 뷰가 없는 이전 서버에서는 기존 발견 카드만 유지하고, 새 설정/계획은 서버 업데이트 안내를 표시한다.

`EXPO_PUBLIC_SUPPORT_EMAIL`의 실제 문의 주소, 성인 인증 제공사, APNs/FCM/EAS와 실제 push worker, 스토어용 공개 약관 URL, 정식 법적 문서·동의 버전, 운영 dev 테스트 예외 분리/복원은 미완료다. 키만 설정하면 성인 인증이나 푸시 발송 코드가 자동 완성되는 것은 아니다. expo-crypto 추가로 native 재빌드가 필요하며 서버 비밀 키는 앱에 넣지 않는다.

## 2026-09-24 매칭 상대 설정 배포

- 새 서버/키/외부 서비스는 필요 없다. 기존 DB에 `supabase/migrations/202609240001_match_preferences.sql` 적용이 필요하다. 이번에는 소스와 로컬 DB만 반영했으며 원격은 변경하지 않았다.
- 원격의 기존 마이그레이션 이력과 누락분(정원 037 포함)을 먼저 확인하고 순서대로 배포한다. `db reset`이나 `config push`는 필요 없다.
- 앱 배포 전에 RPC를 적용한다. 미배포 서버에서는 설정 조회/저장이 실패하며 가입 완료를 가장하지 않는다. 기존 기록·친구 기능은 별도 API라 유지된다.
- 일반 사용자 두 계정으로 본인 성별·상대 조건 저장/재접속, 양방향 발견, 성별 미설정 제외, 노출 중단 및 대기 요청 취소, 기존 친구 채팅 유지, 차단 뒤 읽기·쓰기·알림 거부를 확인한다. 익명 RPC/타인 성별·선호 조회는 허용하지 않는다.
- 기존 사용자의 기본값은 성별 미설정·상대 상관없음이다. 성별을 이름·사진·기존 인증 데이터에서 추정하거나 자동 보정하지 않는다.

## 2026-09-14 러닝 정원 후속

격자 배분은 초기 2.5km, EPSG:5179 기준으로 소스에 반영했다. 실제 공공 구간 데이터를 이 좌표계로 변환하고 공원별 대표 지점·고정 ID를 지정하는 적재 작업이 필요하다. 전국 격자마다 임의 포인트를 생성하지 않는다. 격자별 안전 후보 구간 중 최대 한 곳만 배정하고 인접 격자도 조회한다. 앱의 꾸미기 체험은 예시이며 정원 저장/지급 서버 연결을 대신하지 않는다.

일반 희귀 드롭의 서버 난수·보상 원장·중복 지급 방지·정원 저장·방문 권한은 후속 1~5 작업에서 구현하고 로컬 DB에 적용했다. 원격/운영 설정은 변경하지 않았다. 남은 구역 작업은 검토된 구역 데이터, 개방 시간·기상·통제 정보 갱신, 지역별 일일 선정 결과 저장 및 GPS 구간 통과 판정이다. 이는 키 설정만으로 끝나지 않는 후속 서버·앱 구현이며 [상세 계약](running-garden.md)에 구분해 두었다.

### 담당자 적용 순서 — 일반 보상/정원

**2026-09-16 배포 완료:** 아래 CLI 오류 이후 사용자 승인을 받아 로그인된 Chrome의 해당 프로젝트 SQL Editor에서 033~036을 단일 트랜잭션으로 적용했다. 기존 파일은 변경하지 않고 바깥 트랜잭션으로 묶었으며 `schema_migrations`에 버전·이름·원문도 함께 기록했다. PostgREST 스키마를 갱신했고 두 테스트 계정의 정원/친구 API 정상 응답 및 익명 profiles/location_points/get_garden 42501을 확인했다. 아래 적용 순서는 향후 참고이며 같은 마이그레이션을 재실행하지 않는다. 실제 신규 러닝 지급→편집→방문 종단 검증은 남아 있다. CLI 인증 문제는 해결하지 않았다.

2026-09-16 재시도 결과: `npx supabase db push --linked --dry-run`이 로그인 역할 초기화 중 HTTP 403(`Your account does not have the necessary privileges`)으로 거절됐다. 기존 키체인 대기와 달리 이번에는 프로젝트 접근 권한 오류가 확인됐다. 현재 로컬에는 `SUPABASE_DB_PASSWORD`가 없다. 프로젝트 권한이 있는 Supabase 계정으로 CLI 로그인 후 dry-run을 다시 확인하거나, 해당 프로젝트 DB 비밀번호를 로컬 환경변수로 제공해야 한다(대화·git에 기록하지 않음). 예상 미적용 범위는 정원 033~035와 명시적 개발 테스트 친구 036이며, 실제 대상/이력을 확인한 뒤 `npx supabase db push --linked`로 적용한다. reset/config push는 필요 없다. 서비스 역할 키로는 스키마 마이그레이션을 대체할 수 없다.

1. 대상 원격 프로젝트와 기존 적용 버전을 확인하고 마이그레이션 `202608120033`~`035`를 순서대로 모두 적용한다. 034는 033의 검증 SQL 수정, 035는 선택 참여 제어와 과거 워치 기록 소급 방지이므로 일부만 적용한 상태로 개방하지 않는다. 앱의 `.env`, provider 설정, 키는 이번 작업에서 바꾸지 않았다.
2. 기존 검증 worker가 정상 완료되는지 확인한다. 이번 보상은 완료 트리거를 쓰므로 새 외부 서비스·스케줄러·앱용 비밀 키가 필요하지 않다. 기존 worker 장애 시에는 보상도 검증 대기이며 클라이언트가 자체 지급하지 않는다.
3. 익명 요청은 정원 RPC 실행이 거절되고 `location_points`·`profiles`는 42501인지 확인한다. 일반 사용자 두 계정으로 비공개/친구/유효 후보, 차단·관계 제거·성인 인증 회수 뒤 목록과 직접 조회 모두 검사한다.
4. 개발 빌드에서 정원 참여 → 새 러닝 → 서버 검증 → 완주 보상 → 배치 → 재접속 시 유지 → 친구 방문을 확인한다. 500m 이월, 42km 확장, 보상 없는 결과, 통신 실패/동시 편집도 포함한다. 보상 검증을 위해 실사용자의 GPS나 인증 상태를 임의 조작하지 않는다.

로컬 검증은 DB 316개·정원 순수 함수/배치 11개·타입 검사 통과. 현재 Android 에뮬레이터는 원격 dev를 바라보므로 API 미배포 안내까지만 확인했다. 원격에서의 실제 지급·편집·방문 완료를 주장하지 않는다.
